# Circular Buffer: Test File Maintenance Guide

## Overview

The `circular-buffer` exercise in the Exercism TypeScript track uses a **manually maintained** test file. Unlike some other tracks that generate test files from canonical data via a template engine, the TypeScript track has **no per-exercise test-file generator**.

The test file `circular-buffer.test.ts` was written by hand and is maintained directly by track contributors.

---

## Test-Generation Workflow

```
problem-specifications/exercises/circular-buffer/canonical-data.json
            │
            ▼  (configlet sync – UUID tracking only)
exercises/practice/circular-buffer/.meta/tests.toml
            │
            ▼  (manual authoring / review)
exercises/practice/circular-buffer/circular-buffer.test.ts
            │
            ▼  (CI: scripts/helpers.mjs prepare())
       tmp_exercises/circular-buffer.test.ts
       (xit( → it(  to enable all cases; run against .meta/proof.ci.ts)
```

**Key point**: The `.meta/tests.toml` file records which upstream canonical cases are covered (by UUID), but the actual test names, test logic, and test structure in `circular-buffer.test.ts` are written by human contributors. There is no Jinja template, no code-generator binary, and no per-exercise generation script.

---

## Exact "Generation" Command (CI Prepare Step)

There is no generator command that produces `circular-buffer.test.ts`. The file is hand-maintained.

The CI step that runs all tests against the reference implementation is:

```bash
# From the repository root
ASSIGNMENT=practice/circular-buffer corepack yarn test
```

This calls `scripts/test.mjs` → `scripts/helpers.mjs:prepare()` which:

1. Copies `circular-buffer.test.ts` to `tmp_exercises/circular-buffer.test.ts`.
2. Replaces `xit(` / `xtest(` / `xdescribe(` with `it(` / `test(` / `describe(` (enabling all test cases).
3. Copies `.meta/proof.ci.ts` as the solution.
4. Runs `corepack yarn jest --bail tmp_exercises`.

For a **local per-exercise run** without the root-level runner, run from the exercise directory:

```bash
cd exercises/practice/circular-buffer
corepack yarn install          # one-time setup
# Then manually copy proof.ci.ts → circular-buffer.ts for reference testing:
cp .meta/proof.ci.ts circular-buffer.ts.bak   # preserve stub
cp .meta/proof.ci.ts circular-buffer.ts
corepack yarn test:implementation --watchAll=false
cp circular-buffer.ts.bak circular-buffer.ts  # restore stub
```

> **Important**: Never overwrite `circular-buffer.ts` in the working tree. Use a temporary directory for reference testing. The `work/R47-T022/check.py` script handles this safely.

## How to Reproduce / Update the Test File

Since the test file is manually maintained, "regenerating" means editing it by hand while following the track's contributing guidelines:

1. Check the upstream canonical data for changes:
   ```bash
   ./bin/fetch-configlet
   ./bin/configlet sync --exercise circular-buffer
   ```
2. Review the updated `tests.toml` for newly added or changed UUIDs.
3. Manually update `circular-buffer.test.ts` to reflect any new or changed canonical cases.
4. Update `.meta/proof.ci.ts` if the reference implementation needs to change.
5. Verify locally:
   ```bash
   cd exercises/practice/circular-buffer
   corepack yarn install
   # (Use check.py from work/R47-T022/ to run against proof.ci.ts safely)
   python3 ../../work/R47-T022/check.py
   ```
6. Run the full CI check from the repository root:
   ```bash
   ASSIGNMENT=practice/circular-buffer corepack yarn ci
   ```

## Idempotency / Round-Trip Verification

Because the test file is manually maintained (not auto-generated), "round-trip verification" is defined as:

- **Copy A and Copy B** of the exercise directory (unchanged from HEAD) will have **identical `circular-buffer.test.ts` files** because there is no non-deterministic generation step.
- Two independent copies of the exercise directory always produce identical test files; there are no timestamps or random content.
- The only allowed difference between two copies is none — the file content must be byte-for-byte identical.

The `tools/course_checks/r47-t022.py` script verifies this by comparing two independent copies.
